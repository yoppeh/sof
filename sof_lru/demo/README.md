# cachesim

A cache simulator in c: the hit rates of least-recently-used caches of several sizes on a trace of keys.

`cachesim` replays a trace of keys, one per line, from files or standard input, through an LRU cache of each size given with `-s`, all at once, and prints each cache's hits, misses and hit rate. With `-g` it generates the trace instead, from a seed: keys drawn uniformly, or with `-z`, with a Zipf-like skew, in which a few keys are far more popular than the rest, as they are in most real workloads. With `-p` it prints the generated trace, so it can be saved, edited or replayed later.

_main.c_ is the program. The simulation is done by _cachesim.c_, declared in _cachesim.h_, which keeps a `cachesim_t` that the program provides and sets up with `cachesim_init()`, giving the size of each cache. `cachesim_access()` replays one key through every cache, `cachesim_hits()` gives the hits of a cache, `cachesim_clear()` empties the caches and starts the counts over, and `cachesim_free()` releases the simulator's memory. Traces are generated by a `cachesim_trace_t`, set up with `cachesim_trace_init()`, given the number of keys, the skew and the seed; `cachesim_trace_next()` draws each key, and `cachesim_trace_free()` releases it.

Each cache is a `sof_lru_t` that holds its own copies of the keys, so the caches don't affect each other and a key's hits in one cache are those an LRU cache of that size alone would have. A generated trace's keys are the numbers from 0 to _keys_ - 1. With a skew _s_, key _k_ is drawn in proportion to 1 / (_k_ + 1)^_s_, so with 1, Zipf's law, key 0 comes twice as often as key 1 and three times as often as key 2. The weights are worked out once, into a table of their running sums (8 bytes a key), in fixed point with 30 bits after the point: the skew is rounded to a multiple of 1/65536, the base-2 logarithm of each key's rank is found by repeated squaring, and 2 to the power of minus the skew times it from a product of the square roots of 1/2. A key is drawn by finding a random number below the total in the table, with `sof_sort_upper_bound()`. The base-2 logarithms' whole parts, and the scale the weights are given so that their total fits in 63 bits, come from `sof_bit_highest()` and `sof_bit_ceil_log2()`. With no floating point beyond rounding the skew, a seed gives the same trace on every platform and compiler; the tests check some keys that must come out the same everywhere. With a skew of 0, keys are drawn uniformly, without a table.

The caches are [sof_lru](../../sof_lru/) caches, from _../../sof_lru/_ (_sof_lru.c_ and _sof_lru.h_), which find keys through the [sof_hashmap](../../sof_hashmap/) library in _../../sof_hashmap/_ (_sof_hashmap.c_ and _sof_hashmap.h_), whose keys are hashed by the [sof_hash](../../sof_hash/) library in _../../sof_hash/_ (_sof_hash.c_ and _sof_hash.h_, which use [rapidhash](https://github.com/Nicoshev/rapidhash) in _rapidhash.h_, under its own MIT license). Random numbers come from the [sof_random](../../sof_random/) library in _../../sof_random/_ (_sof_random.c_ and _sof_random.h_), keys are found in the table of running sums with the [sof_sort](../../sof_sort/) library in _../../sof_sort/_ (_sof_sort.c_ and _sof_sort.h_), logarithms are rounded with the [sof_bit](../../sof_bit/) library in _../../sof_bit/_ (_sof_bit.h_), and memory is allocated through the [sof_alloc](../../sof_alloc/) library in _../../sof_alloc/_ (_sof_alloc.c_ and _sof_alloc.h_). The program reads its options with the [sof_copt](../../sof_copt/) library in _../../sof_copt/_ (_sof_copt.c_ and _sof_copt.h_). Beyond those, it needs nothing but the c standard library.

    size_t sizes[] = {100, 1000};
    cachesim_t sim;
    cachesim_init(&sim, sizes, 2, NULL);           // no allocator: the standard functions
    cachesim_access(&sim, "key");                  // once for each key in the trace
    size_t hits = cachesim_hits(&sim, 1);          // the hits of the cache of 1000
    cachesim_free(&sim);

    cachesim_trace_t trace;
    uint64_t key;
    cachesim_trace_init(&trace, 10000, 1.0, 42, NULL); // 10000 keys, Zipf, seed 42
    cachesim_trace_next(&trace, &key);             // a key from 0 to 9999
    cachesim_trace_free(&trace);

## Building

    make            # builds ./cachesim
    make debug=1    # builds with debug info and without optimization
    ./cachesim -g 100000 -z 0.99 -s 100,1000,10000   # a skewed trace through three caches

`make` in the library's directory, _../_, builds it with the library, as do `make sof_lru` and `make` from the root of the project.

To build it in another project, copy _main.c_, _cachesim.c_ and _cachesim.h_, with _sof_lru.c_ and _sof_lru.h_ from _../../sof_lru/_, _sof_hashmap.c_ and _sof_hashmap.h_ from _../../sof_hashmap/_, _sof_hash.c_, _sof_hash.h_ and _rapidhash.h_ from _../../sof_hash/_, _sof_random.c_ and _sof_random.h_ from _../../sof_random/_, _sof_sort.c_ and _sof_sort.h_ from _../../sof_sort/_, _sof_bit.h_ from _../../sof_bit/_, _sof_alloc.c_ and _sof_alloc.h_ from _../../sof_alloc/_, and _sof_copt.c_ and _sof_copt.h_ from _../../sof_copt/_, into it. To use only the simulator, _cachesim.c_ and _cachesim.h_ need all of those but the _sof_copt_ files.

## Usage

    cachesim [-h] [-s sizes] [-g keys] [-n count] [-z skew] [-r seed] [-p] [file]...

- `-h`: print the usage message, with the list `sof_copt_print()` makes, and exit.
- `-s` _sizes_: the sizes of the caches, in keys, separated by commas, such as `10,100,1000` (the default). Each size is a cache of its own, and every one sees the whole trace. Each cache allocates room for all its keys at the start.
- `-g` _keys_: generate the trace instead of reading it, with keys from 0 to _keys_ - 1.
- `-n` _count_: the number of accesses to generate (default 1000000).
- `-z` _skew_: the skew of the generated keys, from 0 to 16 (default 0): key _k_ is drawn in proportion to 1 / (_k_ + 1)^_skew_. 0 is uniform, and 1 is Zipf's law; values a little under 1, such as 0.8 to 0.99, are typical of web and storage workloads.
- `-r` _seed_: the seed of the generated trace (default 1). The same seed, keys, count and skew give the same trace on any machine.
- `-p`: print the generated trace, one key per line, instead of simulating it. Replaying the printed trace gives the same results as simulating it directly.
- _file_: the trace to replay, one key per line. A key is the whole line, without its line ending (a newline, or a carriage return and a newline), and empty lines are skipped. With no _file_, or `-`, it reads standard input. Several files are replayed one after the other as a single trace. Files can't be given with `-g`.

`-n`, `-z`, `-r` and `-p` need `-g`. It exits with **0**, **1** if a file couldn't be read or memory ran out, or **2** if the options are wrong.

For example, a million accesses to 100,000 keys with a skew of 0.99, through caches holding 0.1%, 1% and 10% of the keys:

    $ ./cachesim -g 100000 -z 0.99 -s 100,1000,10000
    1000000 accesses to 100000 keys, skew 0.99, seed 1
            size          hits        misses  hit rate
             100        274591        725409    27.46%
            1000        489680        510320    48.97%
           10000        723006        276994    72.30%

the same keys drawn uniformly, where a cache does no better than the share of the keys it holds:

    $ ./cachesim -g 100000 -n 200000 -s 100,1000,10000
    200000 accesses to 100000 keys, skew 0, seed 1
            size          hits        misses  hit rate
             100           232        199768     0.12%
            1000          1973        198027     0.99%
           10000         19387        180613     9.69%

a short trace printed, to be saved and replayed:

    $ ./cachesim -g 5 -n 8 -z 1 -r 3 -p
    2
    1
    0
    1
    0
    0
    0
    2

and the words of the complete works of Shakespeare (see _../../test-data/README.md_), one per line, as a trace of real text:

    $ tr -s ' \r\t' '\n\n\n' < ../../test-data/shakespeare.txt | ./cachesim -s 100,1000,10000
    966506 accesses
            size          hits        misses  hit rate
             100        326257        640249    33.76%
            1000        614860        351646    63.62%
           10000        819121        147385    84.75%

## Functions

`cachesim_error_t cachesim_init(cachesim_t *sim, const size_t *sizes, size_t count, const sof_alloc_t *alloc)`

Initialize the simulator _sim_ the caller provides with _count_ caches, of the sizes, in keys, in the array _sizes_, which is copied, so it can be on the stack. A size can be given more than once. Each cache allocates room for all its keys here. _alloc_ is the allocator for all of the simulator's memory, the caches' included, **NULL** meaning the standard functions (see [sof_alloc](../../sof_alloc/)); it is copied into the simulator, so it can be on the stack. Returns **CACHESIM_OK**, **CACHESIM_NO_MEM** if memory couldn't be allocated, or **CACHESIM_ERROR** if _sim_ or _sizes_ is **NULL**, _count_ or a size is **0**, or _alloc_ has a _malloc_ but no _free_ or _free_sized_; an error leaves _sim_ empty.

`cachesim_error_t cachesim_access(cachesim_t *sim, const char *key)`

Replay one access to the NUL-terminated _key_ through every cache, and count it in `accesses`. A cache holding _key_ counts a hit and makes it its most recently used key; one that doesn't copies it in, evicting its least recently used key if it is full. _key_ is copied, so it can be in a buffer the caller reuses. Returns **CACHESIM_OK**, **CACHESIM_NO_MEM** if a cache couldn't copy the key, in which case the caches before it have counted the access and the rest haven't, and `accesses` isn't counted, so the counts are off until `cachesim_clear()`, or **CACHESIM_ERROR** if _key_ is **NULL**.

`size_t cachesim_hits(const cachesim_t *sim, size_t index)`

Return the hits counted by cache _index_, from **0** to `count` - 1 in the order of the sizes given to `cachesim_init()`, or **0** if _index_ is `count` or more. The cache's misses are `accesses` less its hits.

`cachesim_error_t cachesim_clear(cachesim_t *sim)`

Empty every cache and set `accesses` and every cache's hits to **0**, keeping the sizes. Returns **CACHESIM_OK**.

`cachesim_error_t cachesim_free(cachesim_t *sim)`

Free everything the simulator allocated. The `cachesim_t` itself belongs to the caller and isn't freed; it is left empty. Returns **CACHESIM_OK**.

Every simulator function accepts a **NULL** _sim_: `cachesim_hits()` returns **0** and the others return **CACHESIM_ERROR**. A simulator that was freed, or whose `cachesim_init()` failed, is empty and stays that way: `cachesim_hits()` returns **0**, `cachesim_free()` returns **CACHESIM_OK**, and `cachesim_access()` and `cachesim_clear()` return **CACHESIM_ERROR**, until it is initialized again.

`cachesim_error_t cachesim_trace_init(cachesim_trace_t *trace, uint64_t keys, double skew, uint64_t seed, const sof_alloc_t *alloc)`

Initialize the generator _trace_ the caller provides to draw keys from **0** to _keys_ - 1, key _k_ in proportion to 1 / (_k_ + 1)^_skew_, from random numbers seeded with _seed_ (any value). _skew_ is from **0** to **CACHESIM_SKEW_MAX**, 16, and is rounded to a multiple of 1/65536; at **0**, every key is equally likely and nothing is allocated. Otherwise a table of the weights' running sums, 8 bytes a key, is allocated and filled, which takes a moment for millions of keys, and a key so unlikely that its weight rounds to **0** is never drawn. _alloc_ is as for `cachesim_init()`. Returns **CACHESIM_OK**, **CACHESIM_NO_MEM** if the table couldn't be allocated, or **CACHESIM_ERROR** if _trace_ is **NULL**, _keys_ is **0**, _skew_ is out of range or not a number, or _alloc_ has a _malloc_ but no way to free; an error leaves _trace_ empty.

`cachesim_error_t cachesim_trace_next(cachesim_trace_t *trace, uint64_t *key)`

Draw the next key of the trace into _*key_. Returns **CACHESIM_OK**, or **CACHESIM_ERROR**, leaving _*key_ alone, if _key_ is **NULL**.

`cachesim_error_t cachesim_trace_free(cachesim_trace_t *trace)`

Free the generator's table, if it has one. The `cachesim_trace_t` itself belongs to the caller and isn't freed; it is left empty. Returns **CACHESIM_OK**.

Every generator function accepts a **NULL** _trace_ and returns **CACHESIM_ERROR**. A generator that was freed, or whose `cachesim_trace_init()` failed, is empty: `cachesim_trace_next()` returns **CACHESIM_ERROR** and `cachesim_trace_free()` **CACHESIM_OK**, until it is initialized again.

## Types

    typedef enum cachesim_error_t {
        CACHESIM_OK = 0,
        CACHESIM_NO_MEM,
        CACHESIM_NO_MATCH,      // never returned
        CACHESIM_ERROR,
    } cachesim_error_t;

    typedef struct cachesim_cache_t {
        size_t size;            // the most keys the cache holds
        size_t hits;            // accesses that found their key in it
        sof_lru_t lru;          // the cache, holding copies of the keys
    } cachesim_cache_t;

One simulated cache. The application may read the fields, and walk the keys of _lru_ with `sof_lru_newest()` and `sof_lru_next()`, which don't change it, but should not change anything.

    typedef struct cachesim_t {
        cachesim_cache_t *caches; // count caches, in the order of the sizes given
        size_t count;
        size_t accesses;        // keys replayed
        sof_alloc_t alloc;      // copy of the allocator; zeroed for the standard functions
    } cachesim_t;

A simulator. The fields can be read but should not be changed by the application.

    typedef struct cachesim_trace_t {
        sof_random_t random;    // the generator keys are drawn with
        uint64_t keys;          // the number of different keys
        uint64_t *cdf;          // the weights' running sums, or NULL for a uniform trace
        sof_alloc_t alloc;      // copy of the allocator; zeroed for the standard functions
    } cachesim_trace_t;

A trace generator. The fields can be read but should not be changed by the application. The weight of key _k_ is `cdf[k] - cdf[k - 1]` (`cdf[0]` for key 0), and the total, `cdf[keys - 1]`, is at most 2^63.

## Threading

_cachesim.c_ has no globals and does no locking, so separate simulators and generators can be used on separate threads freely. `cachesim_hits()` only reads a simulator, so any number of threads can call it at once as long as nothing writes to it; every other function writes, `cachesim_trace_next()` included, since it advances the generator. With a readers-writer lock, take the read lock for `cachesim_hits()` and the write lock for the rest. The program uses one thread.
